# launchagents/

User-scope `launchd` plists that survive reboot/logout. Symlink them into
`~/Library/LaunchAgents/` so the dotfile remains the source of truth:

```sh
ln -sf ~/dotfiles/ollama/launchagents/com.user.ollama-env.plist \
       ~/Library/LaunchAgents/com.user.ollama-env.plist
launchctl load -w ~/Library/LaunchAgents/com.user.ollama-env.plist
brew services restart ollama   # re-launch ollama so it inherits the env
```

To verify:

```sh
launchctl getenv OLLAMA_CONTEXT_LENGTH   # → 32768
```

To uninstall:

```sh
launchctl unload ~/Library/LaunchAgents/com.user.ollama-env.plist
rm ~/Library/LaunchAgents/com.user.ollama-env.plist
```

## Why a LaunchAgent and not just `launchctl setenv`?

`launchctl setenv` only writes the **live** user launchd session. Anything
set that way evaporates on reboot, logout, or `launchctl bootout`. A
LaunchAgent with `RunAtLoad=true` reapplies the values at every login.

## Why not put the env directly in `homebrew.mxcl.ollama.plist`?

That plist is generated by `brew services` and gets rewritten on upgrades.
Anything we add by hand would be clobbered. Keeping a separate user-owned
agent means brew can manage ollama and we can manage the env independently.
